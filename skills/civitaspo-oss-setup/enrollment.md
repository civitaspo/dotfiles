# Enroll a client in csm-ci

Use the deployed [server configuration](https://github.com/civitaspo/csm-ci-server/blob/main/csm-ci.yaml) and the matching published [setup](https://github.com/civitaspo/csm-ci-actions/blob/v0.6.0/docs/setup.md) and [repository settings](https://github.com/civitaspo/csm-ci-actions/blob/v0.6.0/docs/repo-settings.md) guides. Inspect the server's current workflow pins first; use the matching version if it differs from these links.

1. Install the Server and Approver Apps on the client. The Client App is installed on the server, where it creates request labels. Provision client repository variables `CSM_CI_CLIENT_APP_CLIENT_ID` and `CSM_CI_SERVER_REPOSITORY` (`civitaspo/csm-ci-server`), and secret `CSM_CI_CLIENT_APP_PRIVATE_KEY` through an authorized secret-management channel. Server and Approver keys stay in the server environment.
2. Add an explicit repository entry to server `csm-ci.yaml` with `approve`, `merge`, `policy-check`, and `securefix`. Add `release` only when needed. Submit the server change through its protected PR process. Confirm the server's trusted approvers, mergers, committers, required checks, and sensitive-path policies apply to the new repository.
3. Add the approval, policy-check, and merge client callers from the setup guide, pinned to a reviewed full SHA compatible with the deployed server. Map `CSM_CI_CLIENT_APP_PRIVATE_KEY` explicitly, not with `secrets: inherit`. Do not check out PR code in privileged `pull_request_target` callers. Ensure the normal PR CI reports the required `status-check`.

   Add a `pull_request` securefix job using the deployed version's [securefix guide](https://github.com/civitaspo/csm-ci-actions/blob/v0.6.0/docs/securefix.md). Check out the PR head SHA with persisted credentials disabled, run `mise run fix`, then run the SHA-pinned `actions/client/securefix` action in the same job with the Client App variables and secret. Run this secret-bearing job only for trusted same-repository PR heads; skip it for fork and other untrusted PRs while still running unprivileged lint and tests. The action submits changed files to the server; it sends no request when nothing changed and skips fork PRs. Confirm the server permits workflow changes when fixes modify `.github/workflows/**`. Test a same-repository PR with a fixable change and confirm the server applies the changes and CI passes on the new head.

4. Verify the callers and CI on the default branch before dispatching `csm-ci-repo-settings`. Follow the versioned guide's activation preflight and target selection. When using server-managed caller distribution, apply `managed-files` first, review and merge its PR through the existing process, then verify callers and required checks before dispatching `all`. Repo-settings does not install Apps or distribute credentials.
5. Check that the server trusts Renovate as a bot merger and permits bot merge requests for this repository. The server verifies that the requesting bot owns the PR and its effective commits; it still requires the current approval, policy, and checks. Confirm the deployed server supports the requested merge flow before enabling Renovate automerge.

`/approve` cannot approve untrusted commits. A human reviews contributor PRs in GitHub when server approval is ineligible. Preserve the current protection rules and use the documented owner-authorized recovery procedure if activation or merging fails.
